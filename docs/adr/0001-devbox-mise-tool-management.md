# ADR-0001: 開発ツール管理の方針（Devbox / Mise）

## ステータス
採用（Accepted）

## 背景と課題
ローカル開発環境の構築において、PostgreSQLなどのシステム依存パッケージ、Rubyなどの言語ランタイム、およびプロジェクト固有の各種ツール（Linter, Git Hook等）のバージョンと依存関係をどのように管理するかが課題であった。
特に、Nix(Devbox)のみで言語ランタイムまで管理しようとすると、エコシステム特有のパッケージマネージャとの競合（例: RubyのGemでのduplicate警告など）が発生しやすいため、適切な役割分担が必要であった。

## 決定事項
ツールの特性に応じて、以下のレイヤーで管理を分担する設計を採用した。

1. **Mise (`mise.toml`)**: 言語ランタイムのバージョン管理
   - 自身のエコシステムを持つ言語（Ruby, Node.js, Bun）は Mise で管理する。
2. **Devbox (`devbox.json`)**: システムパッケージおよび単体バイナリツール
   - DB関連: `postgresql@18`
   - Git・CI支援: `lefthook`, `act`, `actionlint`, `pinact`, `gh`
   - Linter系: `yamllint`
   - 汎用CLI: `jq`
   - ファイル監視: `watchman`
   - `mise` 自体のインストールも Devbox 経由で行う。

## 結果と影響
### メリット
- 言語ランタイムのインストールやアップデートが、Nixpkgsの更新を待たず即座に行える。
- Devbox起因のパス競合や不要なwarningを回避できる。
- ツールの「本来の居場所」に配置されるため、設定ファイルや管理方法が自然になる。

### デメリット
- 管理ファイルが `devbox.json` と `mise.toml` に分かれるため、新しいツールを導入する際に「どこに追加すべきか」の判断コストがわずかに生じる。（本ADRの原則により解決を図る）
